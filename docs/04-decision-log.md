# 关键决策记录

日期：2026-10-26。以下为本次 AI 辅助实现的实际技术选择；候选人须理解并自行复核。

## D01 · 标准库全栈与 SQLite

背景：题目要求前端、后端和持久化，本地快速复现，不限制栈。

备选：React + FastAPI + 数据库服务；Node.js 框架 + SQLite；Python 标准库 + 原生前端。

选择：最后一种。同源 HTTP 清晰分层、无需安装包或构建，适配当前 Windows 环境。代价：手写路由/参数校验及前端状态，不适合继续扩成大型复杂应用。后续若上线，应迁移成熟服务框架与身份体系，保留独立业务/匹配模块。

## D02 · 离线文本模拟 AI

背景：题目允许可复现模拟接口，评审不能依赖付费模型或密钥。

备选：云端大模型、下载本地 embedding 模型、确定性字段/文本匹配。

选择：字符二元组与同义词加权匹配，新规则使用 `offline-text-v2` 并保留初版 v1，解释来自实际字段结果。无外传、无调用成本、完全可复算。代价：不理解复杂语义，12 组样例通过不代表真实准确率；图片不参与评分。后续可新增语义模型，但必须保留旧引擎用于历史复算，不能用模型分数代替私密特征核验。

## D03 · 冻结规则和输入快照

背景：管理员调整权重后，每条推荐仍需追溯当时规则、重复计算；原记录会删除或结案。

备选：只保存 rule_id，重算时读取当前记录；保存完整含隐私记录；保存公开必要字段快照。

选择：第三种，快照不含 contact、secret_hash 或图片；连同原结果、rule_id 和算法版本保存。代价：额外存储，来源已删时推荐详情页不可再展示当前记录。后续需给快照保留期限及隐私删除机制，不能声称无限保留适用于生产。

## D04 · 私密特征哈希 + 人工确认

背景：不能仅凭公开外观认领；敏感联系方式通过前不得公开。

备选：存答案明文供审核员查看；模型判断答案；哈希比较再由发布者/管理员确认。

选择：NFKC/忽略大小写与空白后 PBKDF2 带盐哈希比对，只存布尔核验结果，不存申请答案明文。错误特征不能批准。通过后仅双方/管理员可见联系人。代价：只支持规范化精确回答，不接受自由同义回答；没有现实身份认证。后续若加入人工更正，应单独设计受审计的补证流程。

## D05 · 事务与软删除

背景：多申请并发核验可能双重认领；删除、驳回、结案须留痕。

备选：前端禁用按钮；简单逐条 UPDATE；数据库事务+部分唯一索引。

选择：`BEGIN IMMEDIATE` 重查并串行化关键写入，状态与审计同一事务，已批准/已完成部分唯一索引兜底。删除为状态，不物理删记录。代价：SQLite 同时仅一个写者，适合小规模本地验收；没有撤销核验、重开结案等补偿流程。

## D06 · 审查后修正

- 首版状态选项仅有中文显示文字，提交值与后端枚举不一致。以浏览器失败回归定位，改为显式 option value；8 条开放样例筛选不再变成 0 条。
- 首版未关联失物时缺少认领人联系人。增加私密申请 contact、幂等列升级及通过后裁剪输出，补单元和浏览器测试。
- 首版私密答案仅排除标题/描述/问题重复。审查发现颜色/地点等可直接泄露答案，扩为所有公开文字字段，新增回归。
- 同义词“一食堂”误改已有“第一食堂”，新增归一化幂等测试后用前缀约束修正。
- 复核历史兼容：上述算法修正升级为 v2，保留 v1 的原行为和替换顺序；旧规则和旧快照均绑定实际版本，新增跨版本复算回归。旧申请新增联系人列时按关联失物幂等回填，补旧库升级测试。
