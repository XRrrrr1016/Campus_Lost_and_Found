## 6. 第二轮（首轮开发：核心测试与实现）

对应计划 R2–R3；继续执行原始代码实现授权，没有新的“只做文档”限制，也没有收到逐任务 Git 提交要求。

已发生的协作：

- AI 先写 `tests/test_core.py` 和 `tests/test_matching.py`，实际运行时 9 项因业务服务/匹配器尚未实现而失败。
- AI 实现 `src/database.py`、`src/matching.py`、`src/service.py`，包含 SQLite 表、3 账号、样例、字段相似度、私密特征哈希、权限、认领/交接及规则快照。
- 同批 9 项实际通过，说明最初的关键测试确实经历了功能缺失失败和实现后的成功，不以写出测试本身代替运行。

采纳理由：先定义可验证规则，再实现独立业务服务和纯函数；明确把 AI 候选与归属核验分开，减少对外部环境的依赖。

此阶段尚未宣称 HTTP、前端全流程、全部 22 项测试或最终交付包已经通过。所有代码由 AI 编写，未收到人工改动记录。

## 7. 第三轮（首轮开发：HTTP 与界面）

对应计划 R4；在已有业务和测试基础上继续完成前后端。

采纳并已实现：

- 新增 `tests/test_http.py`，5 项先因 HTTP 服务未实现而失败，再编写 `src/server.py` 和 `app.py` 接通。
- HTTP 使用会话 cookie、CSRF、Host/Origin 校验、统一 JSON 错误、静态文件白名单和本地监听。
- 编写 `src/static/index.html`、`styles.css`、`app.js`，完成广场、本人发布、匹配、认领、核验交接、规则和审计界面。
- 前端用浏览器原生 JavaScript 请求 `/api`，由 Python 返回静态资源；没有 Vue 开发服务器或 5173 代理。
- 加入并发业务回归，形成当时 15 项通过的初版；这一阶段的数量不冒称为后来最终 22 项。

该阶段的通过结果没有覆盖后续发现的所有隐私和界面问题，因此继续安排只读审查和真实浏览器验证，而非直接声明所有实现正确。
